# IMD 首发监听与 ETH 实盘买入框架

本地中文控制台 + TypeScript 执行服务。监听官方 API，发现启动后首个符合设置的新 Ethereum 主网币，核验发射交易、代币与 Uniswap v4 池后，用配置的 ETH 金额执行一次真实买入。金额、Gas 和滑点可在页面调整。

**本版只提供实盘入口，不运行 Anvil 买卖模拟，也不提供演练按钮。启动服务本身不会交易，必须导入钱包、保存参数并明确点击启动实盘。API 模式不检测买卖税率或未来可卖性。**

API 模式无需用户提供 IMD 合约清单、Hook 白名单或起始区块，可提前启动等待新的主网发行。官方 HTTPS API 是发射身份来源；实际地址、事件及参数必须与主网成功交易回执和内置 Uniswap v4 合约代码一致。未知协议版本拒绝执行。

## 当前官方发射网络

2026-10-01 只读核验：[官方文档](https://imd.fun/docs/)、[能力接口](https://api.imd.fun/requests/capabilities) 和 [政策接口](https://api.imd.fun/launch/policies) 当时只公布 Sepolia（11155111）发币。主网付款网络并不等于主网发币支持。这份诊断不阻止 API 模式提前启动等待；当尚无可核验的新主网币时不会交易。

可运行 `npm run protocol:check`（主网），或 `npm run protocol:check -- 11155111`（测试网）查看独立诊断。该命令只读公开接口，不加载钱包；默认检查全部三类项目的兼容性，未全部通过或资料不可用时退出码为 1，不代表每类项目都不能交易，也不作为 API 监听的启动门槛。诊断不替代实际候选的链、成功回执和已支持协议身份校验；未知版本拒绝，不能复制 Sepolia 地址到主网或绕过校验。

## 启动

需要 macOS 或 Linux，以及 Node.js 22 或更新版本。

```sh
npm ci
npm start
```

打开 <http://127.0.0.1:8787>。服务只绑定本机。配置和一次性交易记录保存在 `runtime/`，不进入 Git。不要把控制台反向代理到公网。

1. 在项目目录运行 `npm run wallet:import`，按提示输入专用交易钱包私钥。
2. 回到页面点击「重新加载钱包」，核对公开地址。
3. 设置 ETH 金额、最高 Gas 费用、滑点与最大发射时间差，保存配置并检查主网连接。默认 API 模式无需提供主网清单或 Hook 白名单。
4. 确认真实交易并点击「启动实盘」。此后符合条件的新币可自动触发一次真实买入。

导入工具不回显私钥，不接受命令行私钥参数，在本机 `.env` 中以 `0600` 权限保存。**这是明文文件，没有加密。** 服务启动和重新加载均检查 `.env` 为当前用户私有的普通文件；手工创建文件时先执行 `chmod 600 .env`。页面与状态接口仅返回钱包公开地址。运行中或存在交易记录时禁止重新加载钱包。

## 节点连接

RPC 是读取区块链、报价和提交交易的服务入口，无需自己搭建节点。已预填：

- HTTP：`https://ethereum-rpc.publicnode.com`
- 备用 HTTP：`https://eth.drpc.org`
- WSS：`wss://ethereum-rpc.publicnode.com`、`wss://eth.drpc.org`（高级链上模式，以及具备已核实主网清单时的 API 辅助提示）

这些公共服务在 2026-09-28 的只读检查中通过主网连接验证，但可能限流、故障或更改服务规则，不能保证抢先成交。备用节点也可能共享底层服务。可在本机换成带 API Key 的托管 RPC；不要公开含密钥的 URL。

普通查询默认按 PublicNode 主、dRPC 备的顺序切换；实盘广播同时向多个节点发送同一份签名交易，交易哈希和 nonce 相同，不会因此多买一次。广播不确定时保留原记录，不自动重签或再次下单。API 模式在存在已核实的主网清单和至少两个 HTTP 节点时，也可订阅登记合约事件来提前唤醒 API 查询，并用双节点 HTTP 补扫校对日志。没有该清单时继续仅使用 API，不会把 Sepolia 的地址用于主网。WS 提示本身不授权买入，完整 API 身份、规范区块和候选排序检查仍须通过。

2026-09-29 完成同区块到达时间与固定块读取校验，结果及选择依据见 [RPC / WS 性能比较](docs/RPC_PERFORMANCE.md)。`npm run rpc:benchmark -- 240 runtime/rpc-benchmark.json` 可在本机复测约 4–5 分钟；只读主网数据，不执行买卖模拟或广播。

2026-10-01 的协议适配、链上发现、缓存复用、费用策略及实际节点调整见 [提速记录](docs/SPEED_OPTIMIZATION.md)。本轮尚无新的成交区块差结果。

`npm run rpc:check` 只检查连接，不签名或提交交易。服务说明：[PublicNode](https://ethereum.publicnode.com/)、[dRPC](https://drpc.org/docs/ethereum-api)、[dRPC 限流](https://drpc.org/docs/howitworks/ratelimiting)。

## API 实盘流程

主网默认轮询周期为 2 秒，按每轮开始时间计算；请求耗时计入周期，慢请求不会叠加下一轮。已有配置中的自定义周期保留，可在页面设置为 1–60 秒；升级不会擅自覆盖原来的设置。`Cache-Control: max-age` 记录为响应元数据，不再额外增加等待；429/503 的 `Retry-After` 独立控制退避，链上提示也不能绕过冷却。

- 可在主网发行尚未出现时启动 API 监听；协议诊断和本地主网清单均不是该模式的启动门槛。
- 完整分页建立启动基线，只考虑 Ethereum 主网 `live` 记录；原有项目、测试网和启动前部署的缓存记录不买。
- 最多同时核验两个候选；同一 ID 的并发请求合并。每个候选并行读取 `/launches/:id` 与 `/reads/launch/:id`，随后绑定源码提交、证明、代币、Hook、发射登记及同笔成功交易中的 PoolManager.Initialize。
- 一批已知候选按区块、交易索引和日志索引排序；缺失详情保留重试。候选被官方撤回或期间收到新的候选时重新核对，已锁定交易后出现不一致则停止。
- 选择候选、报价前、签名前及广播前，以链上发行时间、最新链头和本机时钟检查最大发行年龄（默认 120 秒，可设 12–300 秒）；超龄拒绝结果会持久化。交易 deadline 同时受发行年龄和报价有效期限制。
- 核对池参数和内置协议代码，读取实际链上报价、计算正数最低输出、估算 Gas、检查余额和 nonce。API 模式不要求本地税率审核资料或 Hook 白名单；报价及 Gas 估算是构造交易所需的节点调用，不执行本地买卖回放。
- 固定启动时的配置与钱包；等待可能较慢的网络核验完成后重新读取链头，再检查发射区块、候选状态及报价时效，避免沿用慢请求之前的旧链头。状态和交易哈希持久化后，向多个 RPC 并行广播同一份签名交易，等待两次确认；停止或候选失效会阻止尚未发出的广播。

只有首个通过已实现筛选的币会被锁定。锁定后报价、预算或执行失败则停止，不自动换买第二个，也不自动加价重签。跨标签页配置或钱包变化会使原实盘确认失效。

完整核验结果仅在当前进程中短暂复用，最多保留 10 秒；候选集合变化或撤回会使准备缓存失效，旧批次的未完成请求不能作为新批次结果。缓存不代替最终的官方状态、报价、区块哈希、余额和 nonce 检查。

## 税率、滑点和速度边界

**API 模式没有买卖税率检测或卖出测试。** 页面明确显示“未检测”，该模式的税率阈值不参与买入条件，也不使用手填 Hook 白名单。不能把阈值为 0 理解成代币为零税；不能从 API 的 `live` 状态推出安全性或未来可卖性。切换模式不会清除原先保存的链上模式税率和 Hook 设置。

高级链上模式执行 Hook 白名单及本地已审核税率上限。代币和 Hook 代码需精确匹配同一条不可变审核证据；未知、冲突或超出税率上限的组合拒绝购买，签名前再次读取代码。`immutable: true` 必须来自实际审核，包含升级权限、外部依赖和可变税率等行为，不能随意填写；代码哈希本身不能证明无蜜罐或未来可卖性。已知标准委托包装代码拒绝，但这不是通用代理识别器。

滑点是相对池报价的最低池输出限制。恶意代币或 Hook 的后续转账扣减可能影响钱包净到账；最低输出不构成净到账或未来卖出的保证。当前仅支持已验证 Router 版本的原生 ETH → 单个 v4 池路径。

默认费用策略参考最近五个区块的优先费数据，按区块使用率选择建议值。页面中的优先费在该策略下是上限，还同时受最高 Gas 单价和总 Gas 预算约束；也可选择固定优先费。主网费用历史不可用时，使用上限与当前基础费允许额度中的较小值，并记录选取依据。提高优先费可能改善收录机会，但不会自动抬高任何费用上限，也不保证下一块成交。

官方列表此前声明 10 秒缓存、详情声明 30 秒缓存，实际策略可能变化；这些响应头不能证明固定的发布延迟。缩短本地轮询和链上提前唤醒也不能使尚未公开的 API 资料立即出现。只处理启动后公开可核实的新发行，不能保证平台历史第一币、与发币同块或全网第一笔成交。正式主网版本还没有实际成交验证或排名测量，本次提速也没有新的成交区块差可供证明。

v4 PoolManager 的共用 ETH 余额不是单池储备。独立池储备证明尚未接入，页面中的最低已验证储备必须保持 0，设为正数会阻止执行。

## 高级链上监听

可切换到链上模式，通过 WebSocket 新块通知和 HTTP 补扫发现发行。需要在本机提供核实过的 `config/mainnet.json`；可参考 `config/mainnet.example.json`，不能把测试网地址直接当主网使用。

清单必须明确 factory、registry、deployer、协议地址与代码指纹，以及经过审核的不可变 `taxPolicies`。这里的税率判断来自人工审核证据，不进行运行时买卖模拟。`autoStartSafe: true` 仅适用于已审核部署语义的工厂，用于自动查找部署块；历史已有符合条件发行则停止并报告错过。

`src/backrun.ts` / `src/relay.ts` 是尚未接入控制台的独立同块扩展。默认执行流程不会调用 bundle 模拟或提交。完整 pending 识别、部署预测和正式版本验证尚未接入，详见 [扩展说明](docs/ADAPTER.md)。

## 停止和恢复

停止会取消监听及尚未完成的启动请求，**不能撤销已经广播的交易**。`runtime/live/state.json` 的非 `idle` 状态会禁止再次实盘。广播超时记为“不确定”，重启不自动重买。

不要为了再次启动直接删除记录或 `process.lock`；先核对原进程、交易哈希、钱包 nonce 和余额。同一钱包只在一个工作目录运行。本地锁不协调另一份复制目录或外部钱包软件。

API 基线与处理记录跨重启保留；启动前已部署的币，包括停机期间发行，会跳过。修改筛选设置不会重新购买曾跳过的历史项目。

## Sepolia 真实交易测试

独立命令可在公共 Sepolia 网络验证真实买入，复用官方 API 发射核验与 v4 交易编码。它不修改主网控制台配置，也不读取主网 `.env` 钱包。测试网钱包和一次性交易记录保存在被 Git 忽略的 `runtime/testnet/`。

```sh
npm run testnet -- prepare cd74e008-6a11-47be-b242-012cc4529697
npm run testnet -- status
# 公开地址收到免费的 Sepolia ETH 后，发送一次真实测试网买入：
npm run testnet -- buy cd74e008-6a11-47be-b242-012cc4529697
```

测试命令固定链 ID 为 `11155111`，买入金额为 `0.0001` Sepolia ETH，滑点为 1%，最高 Gas 预算为 `0.002` Sepolia ETH。不要向测试地址转入主网资产。发射证据读取优先使用 Sentio：本次检查中 PublicNode 的历史合约代码查询失败，但当前区块报价可用。

该命令购买指定的已上线测试代币，验证 API 核验、报价、签名、广播及到账；不能证明“新币一出现就买到”或主网成交速度。详细结果见 [测试网运行记录](docs/TESTNET_RUN.md)。

需要测量新币发行到成交的区块差时，运行独立的限时监听：

```sh
npm run testnet:watch -- start
npm run testnet:watch -- status
# 已广播后，仅查询这次新币交易，不重新买入：
npm run testnet -- status-fresh
```

窗口为 30 分钟，最多买入一次，沿用测试网金额、滑点及 Gas 上限。先建立完整旧币基线及双节点一致的链上起点，只接受起点之后真实部署的候选；不使用发行编号判断时间先后。旧币测试记录保留，新币记录在 `runtime/testnet/fresh/`。重复启动不会重置窗口或预算；没有新发行就到期结束，不用旧币代替。监听终端按 Ctrl-C 可停止；已广播交易只能查询回执。

结果记录发行、首次 API 发现、报价、成交的区块以及签名和广播时间，核心指标为 `launchToBuyBlocks`。API 首次观察的本机时间与区块时间只能用于近似延迟；单调时钟耗时另列。测试网独立执行器增加了交叉核验，结果不能直接当作主网控制台的速度。流程及计时定义见 [新币观察说明](docs/TESTNET_WATCH.md)。

### 持续监听

持续模式没有 30 分钟截止，独立保存在 `runtime/testnet/continuous/`，保留前一轮记录。仍只对首个通过核验的新币尝试买入一次；随后继续记录发行，但不会自动买第二个。临时网络故障持续退避重试，重启保留起点、首次发现时间和已使用预算。发行时间超过 120 秒的候选会跳过，避免恢复连接后追买旧币。

持续模式按每 2 秒启动一轮的目标调度，API 与节点检查并行；请求较慢时等待本轮全部结束，不叠加请求，也不再额外等待缓存声明的 10 秒。HTTP 限流按 `Retry-After` 退避。选中后在同一进程复用刚核验过的发行结果，执行前仍检查官方 LIVE 状态、规范区块、余额、nonce、滑点与预算；已成交的候选不会每轮重复检查。

持续模式还监听已核验 Sepolia 登记合约的 WS 发行提示，结合双 HTTP 节点逐段补扫、持久化游标和重组重扫。已在 API 列表中的发行编号可提前关联到 ID 并开始准备，但必须等完整官方资料及链上核验通过才有购买资格。新版本 `PoolInitializationGuard` 仅对已复核的 Sepolia 工厂、登记合约、守卫代码和政策版本开放：manifest 的费用 3000 与实际池费 12500 分别核对，实际部署 PoolKey 必须与初始化事件完全一致；不把协议初始化守卫误当作用户编写的交易 Hook，也不据此推断代币税率。

测试网优先费同样参考近期区块，受 2 gwei 优先费上限及原有 0.002 Sepolia ETH Gas 总预算限制；费用历史不可用时回到节点估算。0.0001 Sepolia ETH 的单次买入金额和已消耗预算保持不变，升级不会再买一次。

```sh
# 启动独立后台进程，关闭对话后仍运行
npm run testnet:supervisor -- start
npm run testnet:supervisor -- status
npm run testnet:continuous -- status
# 查询已记录的持续模式交易
npm run testnet -- status-continuous
# 停止服务并留下持久 STOP 标记
npm run testnet:supervisor -- stop
```

后台监督进程会在监听进程异常退出后尝试恢复；电脑关机、睡眠或断网期间不能实时监听。重启电脑后需要重新运行 `start`；停止后 `start` 不会清除 STOP 标记。也可前台运行 `npm run testnet:continuous -- start`，并自行配置进程管理。

macOS 另提供 `testnet:service -- install|start|status|stop`，用于具备目录访问权限的 LaunchAgent 环境。实际在 Documents 目录部署时，macOS 可能阻止它访问工作目录和日志；服务被加载不等于监听已启动，必须核对 `monitor.json` 的成功查询时间。遇到这类限制使用上述后台监督进程，无须修改系统隐私权限。

`monitor.json` 保存当前状态，`chain-watch.json` 保存链上补扫游标，`logs/YYYY-MM-DD.jsonl` 保存每次轮询、链上提示、发现、错误及结果，`result.json` 保存实际交易回执与发行到成交的区块差。不需要 Codex 定时唤醒；用户询问时读取这些记录即可。

轮询日志包含 API 下载、节点检查和整轮耗时；链上与 API 同一发行编号的观察时间另记为 `chain_api_comparison`，仍须区分 WS 提示与 HTTP 核验来源。执行器的 `stage-timing.json` 使用单调时钟记录各阶段耗时。2 秒是本地调度目标，不代表官方数据每 2 秒更新，也不代表 2 秒内成交。
